# 技術ナレッジを定型フォーマットで1ファイルに書き出す

フォーマットを揃えるのは、人間（Docusaurus）と AI（JSON API）の両方から `title` / `tags` / `TL;DR` で確実に引き当て、表示崩れなく再利用できる状態を保つため。1 記事 = 1 トピックの小さい粒度で、決まった型に当てはめて 1 ファイル書き出す。

## ワークフロー

1. 記録する「1 つの問題 or 知見」を 1 つに絞る。複数あれば記事を分ける（1 記事 = 1 トピック）。
2. 記事の性質に合う型を [references/article-format.md](references/article-format.md) から選ぶ。
   - **型 A（トラブル・ハマりどころ型）**：`遭遇した問題 → 原因 → 解決`
   - **型 B（設計判断・比較型）**：`背景・射程 → 判断軸・比較 → 指針`
   - **型 C（技術解説・仕組み型）**：`概要・対象 → 仕組み・仕様 → 使いどころ・注意点`
3. `title`（プレーンテキスト・結論言い切り）と `tags`（小文字英語ケバブケース、目安 3〜6 個、既存タグ優先再利用）を決め、冒頭に `## TL;DR`（2〜5 行）を置く。
4. 出力形式を決める。**基本は Markdown（`.md`）**。ユーザーが「HTML で」と明示したときだけ HTML（`.html`）で書き出す。
5. ファイルとして書き出す。新規 Markdown のファイル名は **小文字英語ケバブケース**（半角スペース禁止）を基本とする。保存先はユーザーの指示に従う。
6. 書き出し後、表示崩れ防止ルール（太字 `**` と括弧の境界、`<T>`/`<Component />` の欠落なし、コードブロック言語指定、参考リンクの Markdown 記法）を確認する。

## 出力形式

| 形式 | いつ使うか | テンプレート |
|---|---|---|
| **Markdown（既定）** | 指定が無いときは常にこちら | [references/article-format.md](references/article-format.md) |
| **HTML（オプション）** | ユーザーが「HTML で」と明示したときだけ | [references/article-format.html](references/article-format.html) |

- どちらの形式でも **外枠（`title` / `tags` / `TL;DR`）と中身のルール（1 記事 1 トピック / 常体日本語 / 最小コード / 汎用化）は同一**。
- 短い記事（目安 100 行未満）では `## まとめ` を省略し `## TL;DR` に集約してよい。
- HTML でも `tags` は `<meta name="keywords">` に必ず残す（横断検索の手がかりを失わないため）。

## 守ること

- 1 記事 = 1 トピック。迷ったら分割する。比較記事でも共通ボイラープレートを毎回貼らず差分コードに絞る。
- `title` にバッククォートや `"React: "` プレフィックスを入れない。
- `tags` は **小文字英語ケバブケース・1 行配列**で 3〜6 個を目安にする（表記ゆれ・日本語タグを避ける）。
- 文体は常体（「だ・である」調）。会話ログ（「質問者の〜」「AI に調べさせた」）や特定プロジェクト固有の識別子・PR diff 行数は汎用表現へ落とす。
- 整理しすぎて書くのをやめるより、粗くてもまず残す（ただし `title` / `tags` / `TL;DR` と表示崩れ防止だけは外さない）。

**テンプレート（`<…>` を差し替えて使う）**:
- Markdown（既定）: [references/article-format.md](references/article-format.md)
- HTML（オプション）: [references/article-format.html](references/article-format.html)
